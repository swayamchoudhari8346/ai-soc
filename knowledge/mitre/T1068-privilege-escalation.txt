MITRE ATT&CK Technique: T1068 — Exploitation for Privilege Escalation
Tactic: Privilege Escalation
Platform: Linux, Windows, macOS

DESCRIPTION
Adversaries may exploit software vulnerabilities in an attempt to elevate privileges. Exploitation of a software vulnerability occurs when an adversary takes advantage of a programming error in a program, service, or within the operating system software or kernel itself to execute adversary-controlled code.

Security constructs such as permission levels will often hinder access to information and use of certain techniques, so adversaries will likely need to perform privilege escalation to include use of software exploitation to circumvent those restrictions. When initially gaining access to a system, an adversary may be operating in the context of a low-privileged user. Vulnerabilities may exist in privileged programs that can be leveraged to gain higher-level privileges on a system.

RELATED TECHNIQUES ON LINUX
- T1548.001 Setuid and Setgid: Abusing SUID/SGID binaries to run as root
- T1548.003 Sudo and Sudo Caching: Misconfigured sudo rules (sudoers NOPASSWD, ALL)
- T1611 Escape to Host: Container escape to host OS
- Kernel exploit: Dirty COW (CVE-2016-5195), DirtyPipe (CVE-2022-0847)

INDICATORS OF COMPROMISE (IOCs)
LINUX:
- Normal user executing sudo to gain root (especially outside business hours)
- sudo usage by accounts not in sudoers or with unusual sudo rules
- /etc/sudoers or /etc/sudoers.d/ file modifications
- SUID binary execution: find / -perm -4000 -exec run
- Access to /etc/shadow, /etc/passwd (root-only files) by non-root process
- Unusual kernel module loading (insmod, modprobe)
- New cron jobs added under root or privileged users
- Wazuh rules: 5402 (successful sudo), 5403 (failed sudo), 5404 (sudo session opened for root)
- Access to sensitive directories: /root/, /etc/ssh/, /var/log/ by non-privileged user

WINDOWS:
- Token impersonation or manipulation
- UAC bypass techniques
- Named pipe impersonation
- AlwaysInstallElevated registry key abuse

DETECTION METHODS
- Monitor /var/log/auth.log for sudo entries: "sudo: <user> : TTY=pts ; COMMAND=..."
- Alert when a user with UID > 999 (standard user) gains euid=0
- Monitor for sensitive file access (/etc/shadow) by non-root processes
- Enable Linux auditd: audit rules on execve, open syscalls for privileged paths
- Track process lineage: bash → sudo → su or bash spawned as root
- Alert on new user creation, password changes made under sudo
- Monitor crontab modifications (cron.d, cron.daily)
- Wazuh FIM (File Integrity Monitoring) on /etc/sudoers, /etc/passwd, /etc/shadow

RESPONSE ACTIONS (priority order)
1. Collect full sudo log entries and command history from the affected user (collect_logs, L4)
2. Determine if the privilege escalation succeeded and what commands were run as root
3. Isolate the host if active exploitation is ongoing or root shell was obtained (isolate_host, L6 — approval required)
4. Disable the compromised user account immediately if root access was achieved (disable_account, L6 — approval required)
5. Review all commands executed under root context during the incident window
6. Check for persistence: new SSH keys in /root/.ssh/, cron jobs, new accounts, modified sudoers
7. Audit SUID binaries on the system: find / -perm -4000 2>/dev/null
8. If kernel exploit suspected, identify CVE, check kernel version, patch or isolate host
9. Tag any exploit tool hashes or C2 infrastructure discovered (tag_ioc, L4)
10. Notify analyst and escalate if root persistence was established (notify_analyst, L0)

SEVERITY ASSESSMENT
- Failed sudo attempts (single): LOW — policy violation, investigate
- Successful sudo to root by non-admin user: HIGH — possible privilege escalation
- Root shell obtained + access to sensitive files: CRITICAL
- Evidence of lateral movement from compromised root account: CRITICAL

MITRE DATA SOURCES
- Process creation logs with UID/EUID tracking
- Authentication logs (/var/log/auth.log, /var/log/secure)
- Linux auditd syscall logs
- File access logs (auditd -w /etc/shadow -p r)
- Kernel logs (/var/log/kern.log) for module loads and exploit attempts
